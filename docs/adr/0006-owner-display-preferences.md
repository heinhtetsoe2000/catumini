# Owner display preferences

The ledger targets a single **Owner** on mobile web in Myanmar but shipped English-only UI with **Appearance** locked to OS system preference (ADR 0001). We add two Owner-scoped preferences—**Display language** (`en` / `my`) and **Appearance** (Light / Dark / System)—stored on the **Owner** account and applied on every device after login. Before login, a cookie bridges guest pages (Login gate, auth flows); if unset, **Display language** follows browser `Accept-Language` and **Appearance** defaults to **System**. Changes apply immediately from segmented toggles: **EN | MY** on **Profile** and the **Login gate**; **Light | Dark | System** on **Profile** only. Burmese mode loads Noto Myanmar web fonts (English keeps ledger ink typefaces), localizes in-app copy and Laravel validation/auth strings (`lang/my`), fully localizes Gregorian day headers in Asia/Yangon, and leaves **APP_NAME**, **Ks**, Owner-entered expense text, and system emails in MVP unchanged; amounts stay Western digits with grouping. **Display language** ships first; **Appearance** follows as a separate release on the same storage pattern. We rejected English-only with a later i18n pass (new UI would be translated twice), per-device-only locale (same Owner on phone and laptop should match), Login-gate appearance controls (System is enough pre-auth; gate stays minimal), binary Light/Dark without **System** (breaks ADR 0001 default), Save-button-gated toggles (locale/theme switches expect instant feedback), Myanmar numerals (unnecessary MVP complexity), Buddhist calendar dates (out of scope for **Spend date**), and shipping both features in one release (localization is the larger string/font/date sweep).
