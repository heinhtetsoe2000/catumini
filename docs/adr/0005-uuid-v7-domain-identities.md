# UUID v7 domain identities

Auto-increment integer PKs on **Owner** (`users`) and **Expense** rows block future NativePHP offline capture: the device must mint an **Expense identity** before any server round-trip, and that value must remain canonical after sync (client-authoritative — no local→server remapping). Public launch also needs non-enumerable **Owner identity** values in verify-email URLs and multi-account isolation. We adopt **UUID v7** as the primary key on both domain tables, generated by Laravel today (`HasUuids`) and by the NativePHP client later; `expenses.user_id` becomes a required FK to `users.id`. Production data is preserved via an **in-place migration** (backfill v7, swap PKs/FKs); deploy truncates **sessions** (force re-login) and **flushes cache** (aggregate keys move from integer to UUID owner ids per ADR 0004). Framework tables (`jobs`, etc.) stay unchanged. This PR is Laravel-ready only — sync endpoints and client-side generation wait for NativePHP. We rejected keeping auto-increment (offline/sync impossible), ULID (extra convention vs Laravel 12 native v7), UUID v4 (poor index locality), expenses-only migration (double work before public launch), preserving sessions across PK type change (fragile payloads), and `migrate:fresh` (production **Expense** history must survive).
